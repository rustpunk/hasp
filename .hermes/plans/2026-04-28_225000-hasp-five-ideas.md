# Plan: Implement Top-5 Ideation Items for hasp

2026-04-28

## Goal

Implement the five highest-fit ideas from `.hermes/ideations/ideate-2026-04-28-rust-secrets-unified.md` using sub-agents for focused context windows. Each sub-agent owns a narrow architectural slice; the sequence preserves compilation at every step.

## Current State & Assumptions

- `hasp` is a Cargo workspace with 11 backend crates. The core dispatch lives in `crates/hasp/src/lib.rs` as a large `Backend` enum driven by a `dispatch_backend!` macro.
- `Backend` trait and an identical `CustomBackend` trait both live in `hasp-core`. The enum has a `Custom(Arc<dyn CustomBackend>)` variant, proving trait-object dispatch is already accepted.
- `AwsSmBackend` mutates process-wide `HTTP(S)_PROXY` env vars inside a locked `block_on` call (race condition in multi-threaded consumers).
- `Store::get`/`exists` have no memoization; Spall-style consumers pay subprocess / keyring / HTTP costs on every lookup.
- `profiles.toml` is parsed eagerly but URLs are not validated until first use.
- `op://` and `bw://` backends (~700 LOC each) have no automated coverage; `hasp/tests/integration.rs` only exercises `env://`.

## Orchestration Strategy

Use **sequential execution** to avoid merge conflicts. Each phase edits a narrow slice and commits before the next phase begins. The sequence is:

| Phase | Scope | Files touched |
|---|---|---|
| 1a | **Core Refactor** — Replace `Backend` enum with trait-object dispatch; unify `CustomBackend` into `Backend`. Update `Store`, `StoreBuilder`, integration tests. | `hasp-core`, `hasp`, `hasp/tests` |
| 1b | **AWS Reliability** — Remove env-var mutation from `AwsSmBackend::block_on`; use AWS SDK native proxy support. | `hasp-backend-aws-sm` |
| 1c | **CLI Hardening** — URL validation at `profiles.toml` load time. | `hasp-cli` |
| 2a | **Store Memoization** — Add bounded TTL cache to `Store` for `get`/`exists`. | `hasp` |
| 2b | **Subprocess Tests** — Fake-binary integration tests for `op://` and `bw://`. | `hasp-core/test_utils`, `hasp/tests` |

Each phase commits to a named branch (or the main branch with atomic commits) before the next begins. There is no file overlap across phases 1a/1b/1c, so they could in theory run in parallel, but we execute them sequentially per user preference.

## Phase 1a — Core Refactor (Sub-agent: Backend Registry)

**Goal:** Eliminate `dispatch_backend!` and the N×M feature-gate boilerplate by making *all* backends trait objects.

### Proposed architecture

1. **In `hasp-core/src/lib.rs`:**
   - Delete the `CustomBackend` trait (it duplicates `Backend` exactly).
   - Keep `pub trait Backend: Send + Sync { ... }` unchanged.

2. **In `crates/hasp/src/lib.rs`:**
   - Replace `pub enum Backend { ... }` with a thin newtype:
     ```rust
     pub struct Backend(Arc<dyn hasp_core::Backend>);
     ```
   - Provide feature-gated constructors:
     ```rust
     #[cfg(feature = "env")]
     impl Backend {
         pub fn env() -> Self { Self(Arc::new(EnvBackend)) }
     }
     ```
   - Implement `BackendTrait` for `Backend` by delegating to `self.0`.
   - Change `Store` to own `HashMap<&'static str, Arc<dyn Backend>>` (or `HashMap<&'static str, Backend>` where `Backend` derefs to `Arc<dyn Backend>`).
   - Remove `dispatch_backend!` entirely. `scheme()`, `get()`, etc. become single-line delegations.
   - `StoreBuilder::with_defaults()` becomes a flat sequence of `store.register(Backend::env())` etc.

3. **In `hasp/tests/integration.rs`:**
   - Replace `hasp::Backend::Env(hasp::EnvBackend)` with `hasp::Backend::env()`.

### Files to change
- `crates/hasp-core/src/lib.rs`
- `crates/hasp/src/lib.rs`
- `crates/hasp/tests/integration.rs`

### Validation
- `cargo test --all-features` passes.
- `cargo clippy --all-targets -- -D warnings` is clean.
- `cargo doc --no-deps` renders `Backend` as a struct with constructors, not an enum.

### Tradeoffs
- **Breaking change:** Consumers pattern-matching on `Backend::Env(...)` will need to switch to constructors. Acceptable for `0.1.0-alpha`.
- **Runtime cost:** One extra indirection (`Arc<dyn Backend>`) vs. enum variant. Negligible compared to network/subprocess costs.
- **Win:** Adding a new backend drops from 4+ edit sites to 2 (Cargo.toml dep + constructor + builder line). No macro edits.

## Phase 1b — AWS Reliability (Sub-agent: Proxy Fix)

**Goal:** Remove the data-race in `AwsSmBackend::block_on`.

### Proposed approach

1. **Remove env-var surgery entirely.**
   - Delete `proxy_lock`, the `proxy` field, and the `block_on` env-var save/restore logic.
   - Document that `aws-sm://` respects `HTTPS_PROXY`/`HTTP_PROXY` natively via the AWS SDK default credential chain.

2. **If explicit proxy support is required:** build the `SdkConfig` with a proxied HTTP connector.
   - Add `aws-smithy-http-client` (already a transitive dep) to configure a custom connector.
   - Cache the `SdkConfig` per region to avoid rebuilding it per call.

For this plan, **Option 1 is preferred** — removing a broken mechanism is architecturally superior to keeping a racy one. Explicit proxy can be restored later via SDK-native configuration.

### Files to change
- `crates/hasp-backend-aws-sm/src/lib.rs` (lines 91–171, plus `with_proxy` constructor)

### Validation
- `cargo test -p hasp-backend-aws-sm` compiles and passes existing unit tests.
- No `std::env::set_var` calls remain in the AWS backend.

### Tradeoffs
- `--proxy-url` CLI flag becomes a no-op for `aws-sm://` in the short term. Document this in `--help` text or CLI error mapping.
- Multi-threaded consumers (Spall) no longer risk concurrent env-var corruption.

## Phase 1c — CLI Hardening (Sub-agent: Profile Validation)

**Goal:** Catch malformed profile URLs at load time, not at first `get`.

### Proposed approach

In `profiles::load_profiles()`:

1. After parsing `RawProfiles`, iterate every `(profile_name, key, url_str)`.
2. If `key == "proxy_url"`, parse via `hasp_core::ProxyConfig::parse(url_str)?`.
3. Otherwise, parse via `url::Url::parse(url_str)?`. Reject schemes that are not known to at least one backend? No — just validate URL syntax; scheme validation belongs to `Store` at runtime.
4. On failure, return a descriptive error: `"invalid URL in profile '{profile_name}.{key}': {e}"`.

Add `url` to `hasp-cli/Cargo.toml` as a normal dependency (currently only a dev-dependency).

### Files to change
- `crates/hasp-cli/src/profiles.rs`
- `crates/hasp-cli/Cargo.toml`

### Validation
- New unit test in `profiles.rs`: malformed URL in TOML returns `Err` from `load_profiles`.
- Existing `hasp-cli` tests still pass.

### Tradeoffs
- Load-time validation means `hasp` commands fail fast even for profiles the user never intends to use. This is correct — a broken config file should surface immediately.

## Phase 2a — Store Memoization (Sub-agent: TTL Cache)

**Goal:** Absorb repeated `get`/`exists` calls inside a single process lifetime.

### Proposed approach

1. Add a cache field to `Store`:
   ```rust
   struct CacheEntry {
       secret: SecretString,
       fetched_at: Instant,
   }

   pub struct Store {
       backends: HashMap<&'static str, Backend>,
       cache: RwLock<HashMap<String, CacheEntry>>,
       ttl: Option<Duration>,
   }
   ```

2. Expose `StoreBuilder::cache_ttl(Option<Duration>)`.
3. In `Store::get`:
   - Check cache first. Hit → clone `SecretString`, return.
   - Miss → fetch from backend, insert into cache, return.
4. In `Store::put`/`delete`:
   - Invalidate the matching cache key (and any prefix matches for `list` safety).
5. In `Store::exists`:
   - If cache has a fresh `get` entry, return `true` without backend hit.
   - Otherwise, delegate to backend (cache `exists` as a boolean? Optional — start with `get` memoization only).

### Files to change
- `crates/hasp/src/lib.rs`

### Validation
- Unit tests in `hasp/tests/integration.rs`:
  - Call `store.get("env://X")` twice; second should serve from cache (prove by temporarily unsetting env var after first call).
  - Call `store.put(...)` then `store.get(...)`; assert cache is invalidated and fresh value is returned.

### Tradeoffs
- `SecretString` must implement `Clone` (it does in `secrecy 0.10`). Verify with `cargo build`.
- Memory usage is bounded by the number of unique URLs fetched. No LRU eviction needed for the initial scope; `HashMap` growth is acceptable for CLI-sized workloads.
- `RwLock` gives concurrent reads. `std::sync::RwLock` is sufficient; no need for `parking_lot`.

## Phase 2b — Subprocess Backend Tests (Sub-agent: Fake Binary Tests)

**Goal:** Give `op://` and `bw://` automated coverage without real 1Password / Bitwarden accounts.

### Proposed approach

1. **Extend `hasp-core/src/test_utils.rs`** with a `FakeBinaryGuard`:
   - Creates a temp directory.
   - Writes a shell script named `op` (or `bw`) to that directory.
   - Prepends the temp directory to `PATH` via `std::env::set_var("PATH", ...)`.
   - Restores original `PATH` on drop.

2. **For `op` fake binary:**
   - Accept `read <url> --format json --no-newline`.
   - Echo a canned JSON response or error exit code.
   - Support `OP_SERVICE_ACCOUNT_TOKEN` check: fail fast with exit 1 if missing.

3. **For `bw` fake binary:**
   - Accept `get item <name>`.
   - Echo canned item JSON shaped like Bitwarden's output.
   - Support `BW_SESSION` check.

4. **Add `#[cfg(feature = "op")]` and `#[cfg(feature = "bw")]` integration tests in `hasp/tests/integration.rs`:**
   - `op_get_roundtrip`: assert `store.get("op://Vault/Item/field")` returns the canned secret.
   - `op_exists`: assert `store.exists(...)` returns true/false based on fake exit codes.
   - `bw_get_roundtrip`: assert `store.get("bw://item/login.password")` extracts the right field.
   - Error mapping tests: fake binary returns exit 1 with stderr "not found" → assert `Error::NotFound`.

### Files to change
- `crates/hasp-core/src/test_utils.rs`
- `crates/hasp/tests/integration.rs`
- Read-only reference: `crates/hasp-backend-op/src/lib.rs` and `crates/hasp-backend-bw/src/lib.rs` (for exact CLI args)

### Validation
- `cargo test --all-features` includes new `op` and `bw` tests.
- CI passes without `op` or `bw` CLI installed.

### Tradeoffs
- Fake binaries must stay in sync with real CLI args. Document this in a comment near the fake-binary templates.
- Tests verify contract conformance, not real 1Password/Bitwarden semantics. This is sufficient for a secrets-router library.

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Phase 1a refactor breaks downstream (Spall) compilation | Spall is not yet depending on `hasp` (pre-alpha). Accept the breaking change and document in `CHANGELOG.md`. |
| `secrecy::SecretString` is not `Clone` | Verify with `cargo build` immediately in Phase 2a. If false, wrap cache entries in `Arc<SecretString>` (requires `Arc` anyway, so cache returns a clone of the `Arc`). |
| AWS SDK native proxy config is non-trivial | Phase 1b deliberately removes explicit proxy rather than half-implementing SDK connector configuration. |
| Sub-agent 2b fake binaries drift from real CLI | Add a comment block in `test_utils.rs` listing the exact commands the fake binaries emulate, with pointers to the real backend source lines. |

## Open Questions

- Should `Store::list` also be memoized? Likely not — list results change frequently and are cheap relative to `get`.
- Should cache invalidation be prefix-based (e.g., invalidate `vault://secret/*` on `put`)? Start with exact-key invalidation; prefix invalidation is future work.
- Should the `Backend` newtype expose `inner: Arc<dyn Backend>` as `pub`? No — keep it opaque to preserve the invariant that `scheme()` is the lookup key.
